Prompt philosophy: One class or one function per prompt. Never one prompt for an entire system. Each prompt must include: file path, exact function signatures, Pydantic schemas where needed, error handling requirements, and at least one test to run after. After every prompt: test, commit, then move on.

The three non-negotiable rules:
1. Never start a new week's work until the current week's deliverables are all working and committed to git.
2. Never build the UI while the backend has untested failure paths. The TUI starts Week 15, not before.
3. Never give Antigravity a prompt that spans more than one file or one class. One prompt → one unit of work → one test to verify it.
