# HERMES Production Root-Cause Matrix

| ID | Boundary | Failure Mechanism | Root Cause | Surgical Repair | Verification Evidence |
|---|---|---|---|---|---|
| **RC-01** | Orchestrator vs Benchmark Runner | Benchmark 1/80 failure rate on multi-file tasks | Single-turn `Orchestrator.run()` could only emit 1 tool call, leaving secondary files (e.g. test files required for pytest) uncreated | Wired `MissionPlanner` and `MissionRunner` into `BenchmarkRunner.execute_task()`, allowing end-to-end task decomposition and multi-step execution | Phase O verified: created module + test file + pytest passed 100% |
| **RC-02** | Planner vs Task Scope | Massive task explosion (8-25 tasks) on simple prompts | `_parse_intent()` classified any prompt > 12 words as a complex web application, invoking `_llm_decompose` with a forced rule "Minimum 8 tasks" | Refined `is_complex_mission` to true web application keywords, preserved atomic task prompts, and split on natural multi-task conjunctions (`and write`, `also write`) | `SYNTH_01` parsed into exactly 1 atomic task; completed in 1 turn |
| **RC-03** | Planner vs File Paths | Single files treated as project directories | Regex `r'generated_projects/([\w\-]+)'` stripped `.py` from filenames, treating `synth_probe.py` as a directory `generated_projects/synth_probe/` | Corrected regex to check file extensions; files now preserve parent project root (`generated_projects` or `workspace_root`) | File written to exact path `generated_projects/synth_probe.py` |
| **RC-04** | Tool Layer vs Content | Code corruption and newline mangling on Windows | `tools/file_tools.py` performed aggressive blanket replacements (`\\n` -> `\n`, `\\"` -> `"`) and default Windows `open(mode='w')` translated `\n` to CRLF (`\r\n`) | Removed destructive replacements from `_clean_code_content()`, added `newline=""` for byte-level pass-through fidelity | `verify_byte_level_integrity.py` passed: exact 26 bytes and 0x0A newlines matched byte-for-byte |
| **RC-05** | Validator vs Parameters | Parameter name divergence (`TargetFile`, `CodeContent`) | Model generated schema aliases not recognized by `core/tool_validator.py` | Added `TargetFile`, `target_file`, `CodeContent`, `code_content` aliases to `PARAM_ALIASES` | Parameter normalization maps aliases to canonical parameters cleanly |
| **RC-06** | Parser vs Prompt Demos | Strategy 4/5 fallback emitted placeholders (`"full content here"`) | `_try_emergency_extraction` and fallback parser allowed empty parameter dicts or demo placeholders when JSON was malformed | Added strict parameter validation: tools requiring parameters (`write_file`, `read_file`, `bash_exec`) reject `{}` and reject demo strings | Model hallucinations or truncated strings fail gracefully rather than corrupting files |
| **RC-07** | Telemetry vs Tool Lifecycle | Tool failure produced `tool_calls = 0` in aggregate telemetry | Uncaught exceptions during tool execution bypassed `telemetry.record_tool()` | Added tool failure recording in exception handler (`success=False`, `exit_code=1`), removed duplicate `finish_request()` call | Failed and successful tools accurately recorded in request spans |
| **RC-08** | Task Queue vs Zero-Tool | Zero-tool conversational queries crashed pipeline | `core/orchestrator.py:535` called `mark_completed(db_task_id, result=...)` with invalid keyword argument | Corrected keyword argument to `mark_completed(db_task_id, db_path=DB_PATH)` | Zero-tool test passed: `tool_count=0`, `stage=12`, `success=True` |
| **RC-09** | Escalation vs Provider Failure | OpenRouter HTTP 402 falsely logged as T3 arbitration success | Tier 3 exception/failure did not reset `result.tier3_was_called` or record failed T3 telemetry | Explicitly set `result.tier3_was_called = False` on failure, logged `cost_usd=0.0` and `success=False` | Verified in Phase O logs: T3 logged `cost=$0.0000`, `success=False`, pipeline completed with `tier3=False` |
| **RC-10** | Mission Runner vs Task Scoping | Cross-task file pollution in structured feedback | `MissionRunner` evaluated `self._files_created[-3:]` in `StructuredFeedbackGenerator`, evaluating old files against new task criteria | Scoped structured feedback strictly to files modified in the active task iteration | Eliminated infinite repair loops on unrelated files |
